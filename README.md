# 매일세법 · 자동 수집 서버 0.2

설치된 매일세법 Android 0.1.0 앱에 연결하는 보고서 생성기입니다. Python 3.11 이상과 인터넷만 필요하며 외부 Python 패키지, AI API 키 없이 실행합니다.

## 현재 구현된 기능

- 국세법령정보시스템의 전체해석례와 전체판례·결정례 등록일 검색을 수행합니다.
- 조회 결과 총건수와 모든 페이지의 문서 수를 대조합니다. 날짜 필터가 무시되거나 결과가 중간에 바뀌면 실패 처리합니다.
- 목록의 등록일과 상세 등록일, 생산일을 각각 보관합니다.
- 공식 요지와 답변·결정·판결내용 및 상세 원문 앞부분을 출처 표시와 함께 앱에 제공합니다. AI가 생성한 법률 해설은 아닙니다.
- 문서 ID와 원문 해시로 신규·변경을 감지하고 SQLite에 원문 텍스트와 변경 이력을 저장합니다. 앱 기본 샘플 14건의 ID를 유지하므로 보관 기록이 연결됩니다.
- 최근 7일을 겹쳐 재검색하고, 실행을 놓쳤으면 마지막 성공일까지 거슬러 수집합니다. 오늘 등록 자료도 조회하지만 하루 전체가 확정되었다는 의미는 아닙니다.
- 기존 문서 중 가장 오래 확인한 20건도 매 실행마다 재확인합니다. 등록일이 바뀌지 않은 본문 수정은 이 순환 검사에서 발견합니다. 최초 수집 범위 밖의 과거 자료 전체를 역수집하지는 않습니다.
- 응답당 최대 3회 재시도, 요청 간 최소 1초, 실행 중복 방지, 원자적 파일 교체를 적용합니다.
- 정상적인 0건과 수집 실패를 구분합니다. 실패 시 이전 정상 보고서를 유지하고 작업을 실패로 표시합니다.

## 로컬 실행

```bash
python -m unittest discover -s . -p test_collector.py -v
python collector.py --from 2026-09-08 --to 2026-09-11
python collector.py
```

`public/report.json`은 누적 앱 보고서, `latest-changes.json`은 마지막 실행의 변경 자료, `status.json`은 수집 상태입니다. `state/maeil.sqlite3`은 다음 실행에서 이어받는 원문·변경 이력 저장소입니다. 이 파일을 지우면 과거 수집 이력을 잃습니다.

초기 이관용 실제 보고서는 별도로 제공됩니다. GitHub의 첫 실행에서는 최근 7일을 다시 수집합니다. 과거 자료가 더 필요하면 로컬 날짜 지정으로 먼저 수집한 뒤 상태를 이관해야 합니다.

## GitHub로 매일 실행하기

제공한 `.github/workflows/daily.yml`은 **설정 파일이며 아직 온라인에 설치되거나 실행되지 않았습니다.** 다음 절차는 GitHub 게시 동의 후에 진행합니다.

1. GitHub에 `maeil-tax-feed` 저장소를 만듭니다. 이 폴더의 코드·테스트·워크플로를 기본 브랜치에 올립니다. APK, 서명키, 작업 폴더, 인증 토큰은 올리지 않습니다.
2. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다.
3. Settings → Actions → General에서 필요한 Actions 실행 및 워크플로 쓰기 권한이 허용되는지 확인합니다. 조직 정책이 막으면 소유자가 허용해야 합니다.
4. Actions → Daily tax reports → Run workflow로 첫 실행을 시작합니다.
5. 성공하면 표시되는 Pages 주소의 `report.json`을 브라우저에서 열어 JSON이 보이는지 확인합니다. 앱 설정에도 이 정확한 HTTPS 주소를 입력합니다.
6. 앱에서 ‘지금 업데이트’를 누르고 자동 업데이트와 알림을 켭니다.

예약은 한국시간 오전 8시 17분 기준입니다. GitHub의 실행 지연과 안드로이드 백그라운드 제한 때문에 정각 알림을 보장하지 않습니다. 휴대전화 재부팅 후 현재 앱은 한 번 열어야 예약이 복구됩니다.

누적 DB와 결과는 `report-data` 브랜치에 저장해 다음 실행에서 복구합니다. Pages에는 `public` 폴더만 게시합니다. 단, **공개 저장소를 선택하면 코드, 요약 보고서뿐 아니라 `report-data` 브랜치의 원문 텍스트·변경 이력도 누구나 볼 수 있습니다.** 북마크·읽음 기록은 휴대전화에만 있으며 서버로 전송하지 않습니다. 수집 응답의 내부 담당자 ID 등은 저장하지 않습니다.

GitHub Free의 Pages는 공개 저장소를 지원합니다. 비공개 저장소에서 Pages를 쓰려면 지원되는 유료 플랜 등이 필요합니다. 비공개 소스 저장소로 만들더라도 일반 Pages 사이트 자체가 자동으로 비공개가 되는 것은 아닙니다. 보고서 비공개 접근이 필요하면 앱 인증과 다른 배포 구성을 먼저 추가해야 합니다. 현재 앱은 인증 없는 HTTPS 보고서만 읽습니다.

공개 저장소의 예약 작업은 장기간 저장소 활동이 없으면 자동 비활성화될 수 있습니다. GitHub Actions 실패 알림을 계정 설정에서 활성화하고, 주기적으로 `status.json`의 `lastSuccess`를 확인하세요. **현재 앱은 서버 수집 상태를 별도로 표시하지 않으므로, 서버가 갱신되지 않아도 파일 다운로드 성공만 표시할 수 있습니다.** 실패한 날에는 Actions 로그와 보고서 상태를 확인해야 합니다.

## 용량과 현재 제한

Android 0.1.0은 누적 3,000건·5MB 제한이 있습니다. 서버는 여유 용량을 남겨 이 한도 전에 오류를 내고 기존 보고서를 유지합니다. 자료를 몰래 삭제하거나 잘라내지 않습니다. 장기 운영 전 앱의 SQLite 저장·페이지별 동기화를 확장해야 합니다. 공개 Git 저장소에 원문 이력이 계속 쌓이는 구성도 규모가 커지면 외부 데이터베이스로 이관해야 합니다.

공식 사이트의 공개 웹 조회 요청을 사용하며 정식 보장된 Open API는 아닙니다. 사이트 응답 구조가 바뀌면 수집기를 수정해야 합니다. 요약이나 상세 본문이 없는 자료, 폐기된 문서 등은 현재 검증 실패로 운영자 확인을 요구합니다. 원문 발췌에는 잘림 표시가 붙으며 첨부 이미지·표를 의미 해석하거나 AI 분석하지 않습니다.
